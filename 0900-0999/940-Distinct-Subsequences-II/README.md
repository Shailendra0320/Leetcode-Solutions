# Problem Statement

Given a string `s`, return the number of **distinct non-empty subsequences** of `s`.

Return the answer modulo:

```text
1,000,000,007
```

A subsequence is formed by deleting zero or more characters without changing the relative order of the remaining characters.

For example:

```text
s = "abcde"
```

`"ace"` is a subsequence, but `"aec"` is not.

The important word is **distinct**: different index selections that produce the same string must be counted only once.

The official constraints are:

```text
1 <= s.length <= 2000
s consists of lowercase English letters
```

# What Is the Question Really Asking?

For a string of length `n`, every character can theoretically be:

```text
TAKEN
or
SKIPPED
```

so there are:

```text
2^n
```

index selections, including the empty subsequence.

But this problem does **not** ask for the number of index selections.

It asks for the number of **different resulting strings**.

For example:

```text
s = "aaa"
```

Index selections can produce:

```text
"a"   "a"   "a"
"aa"  "aa"  "aa"
"aaa"
```

After removing duplicates:

```text
"a"
"aa"
"aaa"
```

This is why duplicate handling is the main difficulty.

---

# Why Brute Force Fails

A brute-force solution would generate all subsequences and put them into a set.

Conceptually:

```text
                    ""
                /        \
             take        skip
              a            a
            /   \        /   \
         take skip    take   skip
          ...  ...     ...    ...
```

There are:

```text
2^n
```

index combinations.

With:

```text
n <= 2000
```

this is completely infeasible.

So we need a dynamic programming solution that counts distinct subsequences without generating them.

---

# Core Observation

Suppose we have already processed a prefix of `s`.

Let the current character be:

```text
c
```

Every existing distinct subsequence has two possible actions:

```text
1. Do not use c
2. Append c
```

Therefore, if there are `X` existing subsequences, we might think:

```text
new count = 2 * X
```

But repeated characters can create strings that already existed.

That is exactly where duplicate handling is required.

---


Appending `a` to every old subsequence creates:

```text

```

But:


already existed.

So simply doubling:

```text

```

would overcount.

We need to remove the part that was already generated by the previous `a`.

# Two Main DP Approaches

We can solve the problem in two closely related ways.

## Approach 1

Keep the number of distinct subsequences grouped by their **ending character**.

```text
dp[26]
```

This is easy to understand because the alphabet has only 26 lowercase letters.

## Approach 2

Keep:

```text
total
+
last[26]
```

where `total` includes the empty subsequence, and `last[c]` stores the total count from before the previous occurrence of character `c`.

This lets us update the answer directly in `O(1)` per character.

---

# Approach 1: DP by Ending Character

## Definition

Let:

```text
dp[c]
```

represent:

> The number of distinct non-empty subsequences seen so far that end with character `c`.

Since the input contains lowercase English letters, there are only:

```text
26
```

possible ending characters.

So:

```text
dp[0] -> ends with 'a'
dp[1] -> ends with 'b'
...
dp[25] -> ends with 'z'
```

The total number of distinct non-empty subsequences is:

```text
sum(dp)
```

---

# Transition

Suppose the current character is:

```text
c
```

Let:

```text
total = sum(dp)
```

Every existing non-empty subsequence can have `c` appended to it.

That creates:

```text
total
```

candidate subsequences.

The character itself also forms:

```text
"c"
```

So the number of subsequences ending in `c` becomes:

```text
total + 1
```

Thus:

```text
dp[c] = total + 1
```

The old `dp[c]` is replaced because all subsequences ending in `c` that were previously counted are now represented by the newer ending-in-`c` set.

# Approach 1: Java

```java
//Approach-1 (DP by Ending Character)
//T.C : O(26 * n) = O(n)
//S.C : O(26) = O(1)

class Solution {
    private static final int MOD = 1_000_000_007;

    public int distinctSubseqII(String s) {
        long[] dp = new long[26];

        for (char ch : s.toCharArray()) {
            int index = ch - 'a';

            long total = 0;

            for (long count : dp) {
                total = (total + count) % MOD;
            }

            dp[index] = (total + 1) % MOD;
        }

        long answer = 0;

        for (long count : dp) {
            answer = (answer + count) % MOD;
        }

        return (int) answer;
    }
}
```

# Approach 2: Total Count + Last Contribution

## Main Idea

Approach 1 repeatedly calculates:

```text
sum(dp[26])
```

We can avoid even that small constant factor.

Maintain:

```text
total
```

where:

```text
total =
number of distinct subsequences INCLUDING the empty subsequence
```

Initially:

```text
total = 1
```

because the empty subsequence exists.

Also maintain:

```text
last[26]
```

where:

```text
last[c]
```

stores the value of `total` that existed **before the previous occurrence of c**.

---

# Why Start With 1?

Because:

```text
""
```

is one valid subsequence.

Starting with:

```text
total = 1
```

makes the doubling recurrence very clean.

At the very end, the empty subsequence is not allowed in the answer, so we subtract one.

---

# The Recurrence

Suppose the current character is:

```text
c
```

Before processing it:

```text
total
```

contains all current subsequences.

Appending `c` to every existing subsequence gives another:

```text
total
```

candidates.

So:

```text
2 * total
```

would be the new count if `c` were appearing for the first time.

But if `c` appeared earlier, some of the new strings already existed.

The number of duplicate states to remove is stored in:

```text
last[c]
```

Therefore:

```text
newTotal = 2 * total - last[c]
```

Then:

```text
last[c] = old total
```

---

# Approach 2 Formula

For current character `c`:

```text
previousTotal = total

total = 2 * total - last[c]

last[c] = previousTotal
```

All arithmetic is performed modulo:

```text
1,000,000,007
```

Finally:

```text
answer = total - 1
```

---

# Why `last[c]` Works

Suppose a character `c` appeared before.

At that earlier point, some set of subsequences was created by appending `c`.

When `c` appears again, appending it to those same earlier states reproduces strings that are already present.

We only need to remember the size of the state space immediately before the previous `c`.

That is exactly what:

```text
last[c]
```

stores.

This prevents duplicate strings from being counted again.

# Approach 2: Java

```java
//Approach-2 (Total Count + Last Contribution)
//T.C : O(n)
//S.C : O(26) = O(1)

class Solution {
    private static final int MOD = 1_000_000_007;

    public int distinctSubseqII(String s) {
        long total = 1;
        long[] last = new long[26];

        for (char ch : s.toCharArray()) {
            int index = ch - 'a';

            long previousTotal = total;

            total = (2 * total - last[index] + MOD) % MOD;

            last[index] = previousTotal;
        }

        return (int) ((total - 1 + MOD) % MOD);
    }
}
```

```cpp
            long long previousTotal = total;
```

# Why We Store `previousTotal`

This part is extremely important:

```java
long previousTotal = total;
```

It must happen **before** changing `total`.

Then:

```java
total = ...
last[index] = previousTotal;
```

Why?

Because `last[index]` must represent:

```text
total BEFORE this occurrence of the character
```

If we store the updated value instead, we would remember the wrong duplicate contribution.

---

# Why We Add `MOD`

The recurrence contains subtraction:

```text
2 * total - last[index]
```

After taking modulo, this value might become negative.

So we use:

```java
(2 * total - last[index] + MOD) % MOD
```

This keeps the result within:

```text
[0, MOD - 1]
```

---

# Why We Subtract 1 at the End

Our `total` includes the empty subsequence:

```text
""
```

But the problem asks for **non-empty** subsequences.

Therefore:

```text
answer = total - 1
```

Using safe modulo arithmetic:

```java
(total - 1 + MOD) % MOD
```

---

# Correctness Proof

## Lemma 1

At any point, `total` represents the number of distinct subsequences including the empty subsequence.

### Base Case

Initially:

```text
total = 1
```

The only subsequence is:

```text
""
```

So the statement is true.

### Induction Step

Suppose `total` correctly counts the current distinct subsequences.

When character `c` is added:

- every existing subsequence can remain unchanged
- every existing subsequence can append `c`

Thus there are initially:

```text
2 * total
```

candidates.

If `c` appeared earlier, some of those candidates duplicate strings already present.

`last[c]` stores exactly the state count responsible for those duplicate strings.

Therefore:

```text
newTotal = 2 * total - last[c]
```

counts each distinct subsequence exactly once.

So the invariant remains true.

---

## Lemma 2

`last[c]` stores the total count immediately before the previous occurrence of `c`.

For each occurrence:

```java
long previousTotal = total;
```

Then after calculating the new total:

```java
last[index] = previousTotal;
```

Therefore the stored value is exactly the old total before the current occurrence.

Thus the duplicate contribution is correctly preserved for the next occurrence.

---

## Theorem

After processing the entire string:

```text
total
```

is the number of distinct subsequences including the empty subsequence.

The problem asks for only non-empty subsequences.

Therefore:

```text
answer = total - 1
```

is exactly the required answer.

Hence the algorithm is correct.

# Common Mistakes

## Mistake 1: Counting Index Selections

The problem asks for distinct strings, not distinct ways to select indices.

---

## Mistake 2: Forgetting the Empty Subsequence

When using the `total` formulation:

```text
total
```

includes:

```text
""
```

So subtract one at the end.

---

## Mistake 3: Updating `last[c]` Too Late

Wrong:

```java
total = ...
last[index] = total;
```

Correct:

```java
long previousTotal = total;
total = ...
last[index] = previousTotal;
```

---

## Mistake 4: Ignoring Modulo During Subtraction

Use:

```java
(2 * total - last[index] + MOD) % MOD
```

instead of allowing negative values.

---

## Mistake 5: Using a Set of All Subsequences

This requires storing potentially exponential numbers of strings and is not feasible.

# 2D DP Is Not Necessary

A common instinct is to create:

```text
dp[i][j]
```

like ordinary subsequence problems.

But this problem asks for:

```text
all distinct subsequences
```

of one string.

We do not need to match another string.

Instead, the important information is:

```text
what strings have already been created
```

and specifically:

```text
which ending character caused the latest duplicate
```

Therefore a 26-state DP is much more natural.

# Final Summary

The problem asks for the number of **distinct non-empty subsequences** of `s`, not the number of index selections.

The naive observation is:

```text
Every character can be taken or skipped
=> double the number of subsequences
```

But repeated characters cause duplicate strings.

To remove those duplicates, remember the previous contribution associated with each character:

```text
last[c]
```

Then:

```text
newTotal = 2 * total - last[c]
```

where `total` includes the empty subsequence.

After processing all characters:

```text
answer = total - 1
```

because the empty subsequence is not requested.

The optimal solution is therefore:

```text
Time:  O(n)
Space: O(1)
```

The constant space is possible because the input contains only 26 lowercase English letters.

---

# One-Line Insight

> **Double the number of existing subsequences for every character, then subtract the duplicate contribution stored for that character's previous occurrence.**
